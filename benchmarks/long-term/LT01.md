# 修改图集中的传输图标

使用包内 Skill 完成绘制，结果保存到 `RUN/`。

## 开始

1. 解压后进入本任务目录，读取 `deterministic-pixel-art/SKILL.md`。
2. 使用 Python 3.10+；需要依赖时，在任务局部虚拟环境安装 `deterministic-pixel-art/requirements.txt`。
3. 用同一个解释器启动记录：

```text
python run.py start --platform "WorkBuddy" --model "当前模型名"
```

工具通过 `python run.py tool <参数>` 调用；配方或辅助脚本通过 `python run.py script <任务目录内的.py路径> <参数>` 调用。这些命令会自动留下记录。

## 需求

`inputs/atlas.png` 是已有图集，`inputs/layout.json` 是其命名单元布局。仅将 `transfer` 改为两支分开的竖直箭头：**左支向上↑，右支向下↓，左右并排**。

继承原色 `D8E3ED`、16×16 单元尺寸和原风格。其余单元的全部 RGBA 像素，以及布局名称、顺序、位置保持不变。

先在 `RUN/initial-notes.md` 用一句话记录准备采用的入口，再完成修改。保留可编辑局部规格、完整图集规格和新布局；查看原尺寸与最近邻放大图，验证改动边界。

## 提交

- `RUN/final.json`、`final.png`、`final-layout.json`。
- 局部规格、原尺寸和放大预览、边界验证结果，以及使用过的辅助脚本。
- 简短的 `RUN/feedback.md`：实际卡在哪里、如何解决、还有哪个步骤需要改进；注明相关命令或文件。

最多两个候选、两轮修正，候选使用新目录。保留失败；无法继续时说明原因。输入、Skill 和记录器保持原样。

```text
python run.py check
python run.py finish --status complete
```

无法继续或额度不足时，最后一条分别用 `--status blocked` 或 `--status quota_limited`。交回 `submission-LT01.zip`；平台可直接导出会话时，一并提供。
