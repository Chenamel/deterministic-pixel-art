# Minecraft 风格储物整理面板

读取`deterministic-pixel-art/SKILL.md`，使用包内工具新画一个模组储物整理界面。目标是Minecraft Java / Forge 1.20.1的自定义界面，按原生逻辑像素设计；本任务交付离线贴图与组合预览，无需启动游戏。不直接交付Skill范例或使用原版游戏素材。

## 开始

使用Python3.10+、Pillow>=10.4,<13；精确复现基准12.3.0。需要时按Skill安装依赖，虚拟环境放在`RUN/`外，环境恢复见`references/workflows.md`。输入、Skill和记录器保持原样；输出与自写源码放在`RUN/`，不用全局安装。

```text
python run.py start --platform "当前平台" --model "平台显示的模型名；未显示则写未披露"
```

后续始终使用同一Python。工具经`python run.py tool <参数>`调用；自写脚本经`python run.py script <任务目录内的.py路径> <参数>`调用，失败也保留。按文件系统选择Skill说明的默认或显式便携输出方式。

## 绘制与组合

需求数值也见`inputs/brief.json`。配色、装饰和绘制表示自行选择；Minecraft预设可选。凹槽、凸起控件和面板应有一致光源，连接处避免断线或重复边框。

1. `RUN/panel/body.json`及`body.png`：176×80、不透明的面板上部。在本地坐标`(8,22)`起绘制3列×3行的18×18凹槽，步长18。标题内容区`[8,6,160,10]`留空，不烘焙文字。右侧为整理控件留位置。
2. `RUN/panel/footer.json`及`footer.png`：176×32、不透明的相接底部；它将直接接在上部下方。底部本地内容区`[8,8,160,16]`留空；上下部共用一套外边框，在连接处不新增横向外框。可编辑规格应能各自独立重渲染。
3. `RUN/buttons.json`、`buttons.png`及工具生成的`layout.json`：四格一行，每格40×16，名称和顺序`normal,hover,pressed,disabled`。绘制一个无文字的整理/转移图标控件，状态在原尺寸下有可辨差异；按下态表现凹陷或位移，禁用态降低强调。状态各自至少有可见像素，Alpha只用0/255，不强制透明边距。
4. `RUN/scene.json`：PNG组合项目。三部分按顺序命名`body,footer,control`，均用`copy`；分别引用`panel/body.png`置于`[0,0]`、`panel/footer.png`置于`[0,80]`、`buttons.png`裁取normal格`[0,0,40,16]`置于`[120,38]`。仅control声明`allow_overlap:true`。画布176×112，设置`require_coverage:true`。通过`assemble`交付`scene.png`、`assembly.json`和`seams.png`。不要手工复制像素拼最终图。
5. 用工具为`scene.png`和`buttons.png`分别生成`RUN/views/<scene或buttons>-<dark或light>-<1或4>x.png`，背景dark=`182637`、light=`E9EDF2`，共8张。所有PNG、布局、组合报告和预览均通过包内工具生成并记录。

实际打开原尺寸和放大图，检查槽位与控件状态、外框连接、内容区和图标含义。需要修正时最多两轮，已查看的探索稿与对应生成源分目录保留，无需凑轮次。保留用过的自写源码。

`RUN/feedback.md`简短写具体困难、最希望改进的一点、实际查看了哪些图，以及游戏内/字体等未验证项。没有困难就如实写没有；无需评分或假装完成游戏验收。

```text
python run.py check
python run.py finish --status complete
```

返回`submission-LT07.zip`。无法继续或额度不足时用`blocked`或`quota_limited`结束并保留已有产物。方便时可附原始会话，不能导出无需重建。
