# 四块水渠驿站与单块修改

读取`deterministic-pixel-art/SKILL.md`及其中的分块指导，用包内工具新画一张原生256×256俯视像素场景。主题是水渠、横跨水面的木栈道和附近的小型驿站；地面至少有两个不同物件，例如小屋、箱子、路牌或植被。风格与配色自行决定，不交付示例的放大版。

## 开始

Python3.10+、Pillow>=10.4,<13；精确复现基准12.3.0。可用兼容的现有环境，缺依赖时按Skill恢复，虚拟环境放在`RUN/`外。输入、Skill和记录器保持原样；产物与自写源码放在`RUN/`，不全局安装。

```text
python run.py start --platform "当前平台" --model "实际显示模型名；未显示写未披露"
```

后续使用同一Python，工具经`python run.py tool <参数>`调用，自写脚本经`python run.py script <任务目录内.py路径> <参数>`调用，失败也保留。按文件系统选择Skill说明的默认或显式便携输出。

## 1. 约定与独立绘制

数值见`inputs/brief.json`。四块各128×128且完全不透明：`nw=[0,0,128,128]`、`ne=[128,0,128,128]`、`sw=[0,128,128,128]`、`se=[128,128,128,128]`。坐标原点在左上，矩形右/下端不包含。

先保存`RUN/contract.json`，包含`version:1`、`size`、`owners`（与brief相同），以及`palette`：五个角色`water,wave,plank,joint,rail`各选一个不同的不透明颜色。其余颜色不限。之后两版共用该约定。

- 水渠全局矩形`[104,0,48,256]`，木栈道覆盖`[0,112,256,24]`，光源和轮廓在跨块处保持一致。水渠、木板的纹理从全局0起算，不能在每块重新归零。
- 为核对纹理相位，保留这些横截面：全局y127、128的整行木板在`x%6==0`时为`joint`，其余为`plank`；x124至131的y112、135为`rail`。水面全局x120、136两条线（不含栈道y112至135）在`y%10==0`时为`wave`，其余为`water`。这些采样线不放其他装饰，其他区域可加光影和细节。
- 右下块含一面矩形小旗，旗面全局`[196,168,8,5]`全部用`F5C26B`不透明色，旗杆与装饰在矩形外。

各块有独立生成入口`RUN/src/nw.py,ne.py,sw.py,se.py`，只绘制自己的本地画布。可共享约定、材料和绘图辅助；不读取其他块图稿，也不先画完整256图再裁四块。每块交付`RUN/v1/chunks/<名称>.json`及工具渲染的同名PNG，规格可独立重渲染。

`RUN/v1/project.json`为PNG组合项目：画布256×256、`require_coverage:true`，四个parts依次nw/ne/sw/se，引用`chunks/<名称>.png`、位置为各块全局原点、`mode:copy`，无重叠。用`assemble`输出同目录`scene.png`、`assembly.json`、`seams.png`和`scene-2x.png`（最近邻2倍预览）。原尺寸、放大图和全部关键接缝实际查看，需要修正最多两轮，已查看的版本与对应源码分目录保留。

## 2. 冻结v1，只改右下旗面

v1选定后先把四个独立生成入口及所用共享源码复制到`RUN/v1/source/`（入口保留nw.py等文件名）。之后保持`contract.json`及整个v1目录不变，再创建v2。把nw/ne/sw三块的JSON和PNG原样复制到`RUN/v2/chunks/`，不重新绘制；只生成/渲染se，把旗面改为`62D8E8`，其余RGBA保持。

v2交付同结构`project.json`、`scene.png`、`assembly.json`、`seams.png`、`scene-2x.png`；组合后不修补整图。用`verify`输出`RUN/change.json`，只允许全局`[196,168,8,5]`变化。检查接缝和非目标区域未变。所有PNG/组合报告/预览/差异报告由包内工具生成并记录。

`RUN/feedback.md`简短记录实际困难、跨块复用方式、查看过的图片、最希望改进的一点和未验证项。没有困难如实写没有，不用评分。

```text
python run.py finish --status complete
```
