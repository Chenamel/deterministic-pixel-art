# rc.5 首轮外部结果：核验结论与改进优先级

2026-10-28（北京时间）。[English](long-term-results-20261028.md) · [机器摘要](measurements/long-term-results-20261028.json) · [长期队列](long-term-testing.zh-CN.md)。本批是单版、有限样本的上手测试，不是新旧版配对或模型排名。

## 结论

**三份提交的工程契约全部独立通过；LT01 的方向和改动边界通过复检，LT02 的消费端仍有值得修正的图文状态一致性问题。** 没有发现新的核心渲染或区外误改缺陷。可读配方与命名单格入口确实被外部使用者找到并完成，但没有对照数据证明普遍节省 token、时间或提高审美。

收到三份 submission、三份原始制作会话（MiniMax 会话在其 ZIP 内）、原始两个任务包，以及 Gemini 的 `review.md`。未收到 Gemini 的 `review.json` 或原始审阅会话，不要求为此重跑整套。协调端匹配了报告中的 21 行图片文件/RGBA 哈希；这能支持其针对正确产物作评，不能独立证明它实际执行过每一次看图或重渲染。

总计 **35 条命令、3 次非零退出**。失败分别是 DeepSeek 辅助脚本候选路径写错、MiniMax 自写校验器混用图集/消费端坐标，以及对 88×18 命名单格申请超过预算的符号网格；前两项已由参与者自行修正，后一项改成局部区域成功。

协调端没有执行外部提交的 Python。使用与冻结包字节相同的可信记录器，在隔离副本重新运行三次检查；另独立重建 **6 组规格/PNG** 及 **3 组导入/局部规格**，核对 RGBA、图集、目标背景和最近邻缩放。最后一次命令快照所列文件无哈希不一致；GLM 的反馈/会话摘录在最后一次记录命令之后加入，不把它们误认成篡改。三份原始制作日志均包含 PNG 打开调用与相应平台模型 ID。

两份 UI 的源图、消费端及主要预览逐字节相同，与确定性配方、相同参数和同一 Pillow 基线一致。会话和辅助脚本不同，没有从这项相同结果推断抄袭、模型等效或能力排名。MiniMax 的实际记录有 13 条命令，早期笔记中的“11条”不是最终计数。

## 反馈取舍与受控复现

| 反馈 | 协调端判定 | 后续处理 |
|---|---|---|
| 按下态图标下移 1px，文字固定 | **已复现**，属于消费端一致性问题 | 优先让文字定位继承状态位移；不改参与者原图或旧任务 |
| 现有预留区完全无法实现图文一起移动 | **过度推断** | 在隔离副本中用普通态文字原点 y=2、按下态 y=3，原检查器通过；该变体仅证明可行，不证明最佳光学对齐。若保留本次普通态 y=3 而仅把按下态改到 y=4，三项边距检查确实失败 |
| 小字号文字存在抗锯齿灰边 | **已复现**；当前基准只接受默认灰度栅格化 | 单独生成 `fontmode=1` 变体，仅两项消费端精确重建检查失败。这是测试契约没有表达栅格化选项，不能归咎于核心渲染器；新协议应显式记录选择，保留旧默认 |
| 点阵字体和最近邻放大保证硬边 | **不成立** | 最近邻保留已有像素；不会去掉字体栅格化时已产生的灰边。是否选单色按字体与风格决定，不强制所有字体阈值化 |
| `START` 看成 `STF`，所以字体有缺陷 | **证据不足** | MiniMax 自制图裁到局部 x=40，截断了 A 并省略后续字母。协调端查看完整 88×18 裁切，标签完整；裁切伪影不能证明原尺寸观察是错的，也不能作为字形缺陷的依据 |
| `inspect --grid` 无法查看 UI | **部分成立，归因需收窄** | 实际失败对象已选 `normal` 单格，仍有 88×18；错误再次建议 `--cell` 没有帮助。无 `--grid` 的完整分析正常，60×18 局部网格正常。改进尺寸/区域错误提示，保留有界输出，不直接放开 256×256 文本网格 |
| 两处宽度示例必然相互矛盾 | **示例用途不清，非渲染错误** | 64px/30px 内容区作为短标签例子合法，但不适配本题 58px 的 `EXPORT MAP`。统一上手例子或标明适用标签，链接真实字体示例 |
| 内容矩形 `y=4..13` 容易误解 | **成立，措辞问题** | 明写 x、y、宽、高与 `y+h<=14` 的半开边界；不改变旧坐标语义 |
| Context 不含 atlas、单传时没有单元 | **可复现，符合分离设计** | 明示成对传 `--context` 和 `--metadata`，或明确使用内嵌布局；不复制第二份容易过期的布局 |
| 缺少字体测量/消费端验证短入口 | **两位使用者共同反馈的真实摩擦** | 下一步优先一个可复用、可选的消费端辅助入口，复用 Pillow，测量实际字体并从布局/预留区生成定位；先不新增三个独立子命令或自动排版系统 |
| 禁用态对比度 3.49:1、短标签留白、勾号小、箭头肩平 | **数值可复现，视觉取舍按需求** | 禁用色对比度为 3.489，提亮候选为 4.762；本任务没有据此规定自动失败。统一宽度导致短标签留白属预期。勾号、肩部可留视觉候选，不改成通用规则 |
| 记录器应捕获所有任意 shell 命令/自动覆盖 | **不采纳直接扩展** | 明确其只记录经由 `tool/script` 的命令，辅助脚本放任务目录；保留新候选目录与显式覆盖。减少输出正文/会话导出负担，比无边界接管 shell 更优先 |

Gemini 将按下态问题列为 LT02 视觉不满足，这一意见保留为消费端修正待项。但单版结果不能称为“新版退步”；也不能从 hover 主要改变填充色，直接推出六态对色弱用户必然退化成三态。当前源图六态互不重复，焦点、按下浮雕和选中标记仍有结构差异。未进行色觉条件或真实交互验证。

## 效率与证据边界

三份 `session.json.tokens` 都是 null，但制作端原始 JSONL 的 `providerData.usage/rawUsage` 实际含按响应计数。之前“完全没有真实计数可获得”的说法需收窄：可以提取已记录响应、去重并标明范围；这些输入含重复/缓存上下文，导出快照可能不完整，还混入后续取证/导出工作。不能当作整项任务计费量、唯一内容长度或新旧版收益。个人用量/余额及原始会话只保存在本地忽略目录，不公开具体用量。

制作端记录命令耗时与会话起止跨度分别保存，二者不等于创作时间。MiniMax 会话有自动压缩事件，且读取配置、编写审查和导出证据耗费很多上下文；这支持缩短测评与消费端工作路径，不支持仅凭 0.08× 判断任务成本。普通用户流程不应要求查宿主数据库来填未知配置。

协调端本次实际查看了 LT01 原尺寸/放大、LT02 原尺寸/放大、诊断拼图和有问题的裁切，并查看三个完整标签/隔离修正视图。相同哈希图不重复看作不同画质样本。审阅是代理复检，非独立人类盲评、游戏内或真实交互验收。

2. **同时清理短路径提示**：网格报错显示所选尺寸和可用区域方案；示例说明标签容量；矩形边界写清；说明哪些命令被记录。继续保留输出预算、拒绝覆盖和失败证据。
