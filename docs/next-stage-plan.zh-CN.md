## 目标与已有基础

目标是让 AI 容易上手、容易修改、容易交付可用的像素资产，覆盖图标、精灵、通用 UI 和可选 Minecraft 风格。判断收益要看任务能否完成、非目标区域是否保留、需要手抄多少信息，以及交付到使用端后是否成立。

当前开发基点为 `e0ed738`，分支 `codex/visual-quality`。v1.2.0-rc.2 已完成本地工程检查：76 个源码测试、61 项整包执行、43 张稳定迁移图与10张外部最终图保持兼容；138个原始/输入文件不变。稳定发布和本地安装仍为 v1.1.1。以上是前一阶段的结果，不是下面计划已经完成的证明。

本次规划又确认一个实际使用成本：

| 当前范例 | 文件字节数 | 行数 | 顶层绘图操作 |
|---|---:|---:|---:|
| 原生128飞船 `sprite-128.json` | 439,756 | 33,744 | 30 |
| 整图控制 `scene-control.json` | 412,335 | 21,469 | 4（内嵌组件） |
| 磨坊组件 `scene/mill.json` | 260,496 | 19,889 | 66 |
| 场景组件清单 `scene-components.json` | 819 | 50 | 不适用 |

原生精灵和不规则区域使用大量显式坐标；它们可以精确渲染，但不适合每次全文交给 AI 修改。仓库中的生成器尚未作为可独立运行的创作配方分发。下一步应优先缩短创作与修改路径，而不是先增加绘制命令或提高尺寸上限。字节/行数是文件成本，不等于模型 token 用量。

## P2：让大资产有可读的创作入口

保留当前 JSON v1 作为可复现、可交换的规格；另外分发少量可以修改的 Python 绘图配方，优先复用现有 `Canvas`、`render` 和拼合 API。颜色职责、轮廓参数、组件位置、尺寸与状态名称用有意义的变量表达。配方与必要资源一起打包，在独立目录可运行，不依赖仓库绝对路径。

先做三种小而完整的配方：图标组、按钮/面板、128原生精灵。场景配方负责先渲染组件再拼合，避免修改 JSON 后继续使用旧 PNG。首版可重渲染全部小组件，不引入缓存、通用构建框架或常驻服务。

实际演练固定为三项：

1. 调整一套图标的强调色，保留其他颜色和布局。
2. 调整按钮宽度、文字预留区及一个状态，保留状态顺序和边框约定。
3. 修改128精灵的指定部件/配色，保留约定轮廓和非目标区域。

过关条件：仅使用分发 Skill 和任务输入即可完成；无修改参数的配方与冻结参考图精确一致；修改后可以从配方独立再生，必要时 `verify` 证明区域约束。记录需要阅读/修改的文件、参数定义数量、实际命令、失败与修正次数。记录重复出现的困难，再决定是否需要新 CLI；不为了一个范例增加通用语法。

不以压缩 JSON 行数代替易用性改进，也不把一张导入网格称作恢复了对象/图层。完整点集、网格和源配方可以并存，按任务选择入口。时间和 token 收益另测，不能从文件变小直接推断。

## P3：把图片放进真实使用流程

先完成一个通用 UI 组件示例，使用真实导出的 PNG、真实文字和明确字体，检查普通、悬停、键盘焦点、按下、选中、禁用等适用状态，以及1/2/3倍整数缩放。示例保持轻量，放在仓库演示资源中，不让核心渲染器新增浏览器或前端运行依赖。

演练“第一次制作 → 放入示例 → 发现问题 → 只改一处 → 更新产物和布局 → 再验证”。例如增加一个按钮或替换图标，检查邻接边缘、状态含义、实际文本预留和背景。将消费端集成问题与 PNG 渲染问题分开记录。

Minecraft 复用同一组件流程并使用独立预设/导出约定，验证槽位、浮雕衔接、UV和状态顺序。输出到独立演示目录，保持原模组资源完整。离线示例、浏览器示例、真实游戏导入分别标记；没有 Minecraft 字体或游戏内验证时不声称完成相关适配。

过关条件：他人从说明可启动示例，能定位每个 PNG 对应的源配方/规格；上述一次真实修改可完整重跑，旧资产契约无关键退步。视觉问题给出具体区域和用途依据，不设自动审美分数。

## P4：真正独立绘制分块

使用新的256场景，不把完成整图再裁成四块作为本阶段结果。先冻结总体草图、调色板、光源、像素尺度、跨边界道路/建筑等关键结构与全局坐标，然后分别完成各块细节。

- 每块明确拥有的最终矩形；额外上下文带是参照或绘制余量，通过 `crop` 去除，不重复覆盖最终像素。
- 用现有 `assemble` 检查矩形覆盖、越界和重叠；整图与接缝同时查看，检查轮廓、材质、光影、道路宽度和结构连接。
- 先采用分文件/分步骤绘制，不要求多模型协作。若实际安排多模型，各自获得同一份约定并记录输入，不能仅因参与模型更多就称更可靠。
- 最多两轮有针对性的接缝修正，保留每轮前后图。仍有关键断裂就记录失败原因，先改善工作流，不继续放大尺寸。

只有256在几何和语义上成立、编辑成本可接受，才测试原生512组件/分块；512不是放大旧图。工具能创建更大画布不代表已经验证其创作质量。
