# 初始优化与 Skill 验证报告

> 这是独立优化阶段的历史实测记录。96 个原文件的完整保护证据保留在本地优化目录；本仓库仅带必要的冻结回归夹具，克隆测试不访问原模组目录。下文的测试日志及包检查文件指当时本地归档；可分发的实测 JSON 位于 [measurements/](measurements/)，当前复跑方法见根 README。

验证日期：2026-10-21。运行环境：Windows，Python 3.14.2，Pillow 12.3.0。

## 结论

质量门禁通过，Skill 已生成在独立目录，未安装到全局技能目录，原目录和模组资源未覆盖。

- 原脚本 18 个，捕获输出 43 张；96 个受保护文件的 SHA-256 最终全部保持。
- 40 张输出的尺寸与解码后 RGBA 像素完全一致；3 张为明确列出的预期变更。
- 24 个 unittest 测试方法通过（含参数化边界检查、43 张逐图回归和 96 文件哈希检查），以 `-W error` 运行，无警告。
- ZIP 包在全新虚拟环境、临时中文与空格路径中解压验证，清除 PYTHONPATH；19 项包级执行检查通过，含标准 Skill 格式校验、4 个示例和新任务。
- 5 个原来静默接受的错误输入现在均明确拒绝；RECT 正确绘出 4/4 像素，原 DSL 为 0/4。
- 未发现 40 张普通迁移资产的像素降级。性能、内存和规格长度并非所有方面提升，代价如下。

## 速度与内存实测

纯渲染每项预热 20 次、测量 400 次。新旧输出先校验一致；不含进程启动、PNG 编码和磁盘。新旧双方均使用预先构造的规格/函数。表中内存为 tracemalloc 测得的 Python 管理内存峰值，不包括 Pillow 原生图像缓冲，不能当作完整进程 RSS。

| 场景 | 原中位 ms | 新中位 ms | 速度倍率 | 原/新 P95 ms | 原/新 Python 峰值 bytes |
|---|---:|---:|---:|---|---|
| panel_128x48 | 1.3364 | 0.1519 | 8.80× | 1.8492 / 0.1864 | 1,569 / 2,868 |
| block_front_16x16 | 0.3214 | 0.1032 | 3.11× | 0.4252 / 0.1111 | 4,501 / 3,044 |
| mode_atlas_80x16 | 0.5105 | 0.4381 | 1.17× | 0.6121 / 0.6557 | 9,085 / 18,383 |

本次图集 P95 从 0.6121 ms 增至 0.6557 ms；虽然中位值改善，尾部耗时有回退。面板和图集的 Python 内存峰值增加，方块面的该指标下降；不宣称全面降低内存。

完整命令另测 12 次，交替执行新旧版本，均生成同一面板与同一 3× 预览共两张 PNG，已确认像素一致：

- 原中位 134.50 ms，新中位 181.53 ms，增加 47.03 ms（35.0%）。
- 原/新 P95：169.51 / 214.27 ms。
- 进程含启动、模块导入、参数处理、读规格、检查和写文件；两边均禁用新 pyc 写入。原命令为提取原代码的隔离驱动，未把原 demo 的四张输出与新命令的两张输出混比。
- 通用 CLI 的检查、参数处理与导入增加冷启动开销；批量或持续调用可直接导入 `render`。该 API 路径已测；未实现或测量专门的批处理 CLI。

第一轮重复校验造成图集约慢一倍，已通过一次校验后复用可信坐标集合修正；原始失败数据保留于 `first-pass-metrics.json`。最终保留公开入口的输入和边界检查，未用关闭检查的版本充当优化结果。机器负载会影响小毫秒量级数据，倍率属于此环境此次测量，不是跨设备性能保证。

## 上下文与行为取舍

- 当前面板原 DSL 为 143 字符，迁移 JSON 为 558 字符，JSON 更长。新工具仍直接支持相同紧凑 DSL，因此简单 MC 面板可选 DSL，不必支付 JSON 长度代价。
- 公共图元与预设避免每次生成完整渲染器代码，但没有实测不同模型的 token、首次正确率或修正轮次；不宣称这些指标已经提升。
- 严格拒绝过去接受的未知指令、重复画布、错误颜色、未知符号和隐式裁切，是有意的行为变化。旧的无效输入不会兼容为静默成功。
- 图集仍需消费端按元数据/契约检查状态顺序。图像验证器无法仅凭颜色与尺寸判断箭头语义。

## 实际包测试与视觉复检

ZIP 共 16 个文件，包含运行时、4 个规格示例、按需参考和 agents 元数据；无虚拟环境、原机器绝对路径、历史脚本、开发测试或原项目资源依赖。运行时唯一第三方依赖为 Pillow；PyYAML 仅用于调用开发阶段的标准 skill-creator 校验器。

在与原项目无关的临时目录内执行了：样例渲染与校验、布局元数据、4 方向命名图集及透明边界、50×18 不透明自定义工具栏、5×3 奇数中心镜像及半透明、DSL、独立预览、坏输入不写输出、导入来源和版本核对。实际程序来自解压的 ZIP，没有使用源码目录回退。

已查看 `comparison.png` 的原尺寸区域和最近邻放大区域：修复后三个红石按钮有完整边框；footer 使用中的顶边形态被保留；16×16 对称徽记、32×32 非对称精灵和 96×40 非 MC 面板均保持整数网格与预期构图。此次是本代理的视觉复检，不是独立盲检，也没有进行游戏内验收。

未验证：其他操作系统、其他 Python/Pillow 组合、不同模型的真实自动选用/创作质量，以及 Codex 全局发现与触发。Skill frontmatter 与 Codex agents 元数据通过检查，默认允许自动调用，但本次只交付本地候选，没有安装到全局目录。
