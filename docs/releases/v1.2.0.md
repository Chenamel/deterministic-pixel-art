# v1.2.0 — PNG import, precise edits and component assembly

Create and edit pixel-art icons, sprites and UI from text specifications or short Python examples. Give individual images names in an atlas, or assemble separately drawn components into a scene. Output is PNG; Minecraft styling is optional.

## Changes since v1.1.1

- Inspect image dimensions, colors, transparency, connected pixel regions and symmetry, or display a small region as a symbol grid. Reports cap the number of listed items to keep output manageable. Choose review backgrounds and reuse existing atlas layouts.
- Import static 8-bit PNGs without reducing colors, preserving RGB values even in fully transparent pixels. Import a whole image or select one named atlas cell after checking its layout. Replace that cell while keeping the other cells and layout unchanged.
- Compare exact RGBA values before and after an edit to check that changes stay inside allowed regions or masks. Assemble PNG components with explicit crops, permitted overlaps and required coverage; inspect seams in coordinate-labeled previews.
- Use editable Python examples for icons, button states, a 128×128 sprite and component scenes. A bridge example draws the left and right chunks separately, with plank patterns aligned across the join. Guides cover small edits, text inspection, visual review and checks in the actual game or application.
- If the filesystem cannot create hard links, set `PIXELART_PORTABLE_OUTPUT=1` once in the terminal for subsequent commands and examples. Per-command options take priority. Overwriting existing files still requires explicit `--force`.

## Compatibility and setup

Python 3.10+ and Pillow >=10.4,<13 are supported. `requirements.txt` pins Pillow 12.3.0 for reproducibility; the reference environment is Python 3.14.2 / Pillow 12.3.0. Runtime dependencies remain Python and Pillow.

JSON v1 and existing API/command defaults remain compatible. Drawing primitives overwrite RGBA; blits use source-over composition unless an explicit supported alternative is chosen. PNG round trips preserve decoded 8-bit RGBA, not necessarily compressed PNG bytes, layers or original drawing instructions. Animation and unsupported high-bit-depth inputs are rejected.

Extract the ZIP, install its `requirements.txt` in the task's Python environment, then run from the extracted parent directory:

```sh
python deterministic-pixel-art/scripts/pixel_art.py render --spec deterministic-pixel-art/assets/gem-16.json --out output/gem.png --preview output/gem-preview.png
python deterministic-pixel-art/scripts/pixel_art.py inspect --image output/gem.png --grid
```

When updating a Skill, keep backups outside the folders the agent scans for Skills, so it does not load both copies. In portable-output mode, another program may read a new file before writing has finished. In any output mode, a program crash or power loss can leave a group of output files only partly updated. After an interruption, check that all expected files are present and complete before using them.

## Evidence and limits

The v1.2.0 release passed 165 source tests, 106 isolated package tests and 43 reference-image checks. Repeated builds produced identical packages, and the Skill passed the official format validation. Of its 98 files, 97 match the accepted development package byte for byte; the remaining module changes only its version constant. `verification.json` records the release commit, its Windows/Ubuntu CI results and the package's source.

External trials cover eight task categories. Records retain LT04's original reversed direction and missing early revisions, and LT08's incomplete early history. These trials do not establish general improvements in image quality, task time or token use. Minecraft game integration, other fonts, artwork drawn directly at 512×512 and drawing by multiple agents remain unverified. Passing automated checks still leaves the image's meaning and appearance to be reviewed.
