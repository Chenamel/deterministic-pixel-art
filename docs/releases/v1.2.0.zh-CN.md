# v1.2.0 — PNG 导入、局部修改与组件拼接

用 JSON 等文本规格文件或简短的 Python 示例脚本制作、修改像素图标、精灵和 UI；也可以将多张小图放进带名称的图集，或将独立绘制的组件拼成场景。输出为 PNG，Minecraft 风格可按需选用。

## 相对 v1.1.1 的变化

- 分析图片尺寸、用色、透明度、相连的像素区域和镜像差异，也可将局部像素显示为字符网格。报告限制逐项列出的数量，避免输出过长；检查图片时可指定背景，并复用已有图集布局。
- 无损导入静态 8 位 PNG：不减少颜色，保留全透明像素里的 RGB 值。可以导入整图，也可以按已核对的布局选取图集中某一格；替换这一格时，其余小图和布局不变。
- 核对图片修改前后的 RGBA 值，确认变化都在指定区域或蒙版内。拼接 PNG 组件时，可明确指定裁切范围、允许的重叠和必须填满的区域，并用带坐标的预览检查接缝。
- 附带图标、按钮状态、128×128 像素精灵和组件场景的示例脚本；另有左右两块独立绘制、木板纹理在接缝处对齐的桥梁示例。文档分别说明局部修改、文本分析、看图检查，以及在实际游戏或应用中检查的方法。
- 如果文件系统不支持创建硬链接，可在终端设置一次 `PIXELART_PORTABLE_OUTPUT=1`，让后续命令和示例脚本使用便携输出模式；单条命令也可单独指定。已有文件仍需明确使用 `--force` 才能覆盖。

## 兼容性与运行

支持 Python 3.10+、Pillow >=10.4,<13。`requirements.txt` 指定 Pillow 12.3.0，便于得到一致结果；发布时使用的环境是 Python 3.14.2 / Pillow 12.3.0。运行只需 Python 和 Pillow。

继续支持 JSON v1，原有 API 和命令的默认行为不变。基本绘图操作直接替换像素的 RGBA 值；`blit` 默认按透明度将新图叠加到原图上（source-over），其他支持的合成方式需单独指定。导入 PNG 后再导出，解码后的 8 位 RGBA 像素值保持一致，但压缩后的文件字节可能不同，也无法恢复原图层或绘制步骤。不接受动画和不支持的高位深图片。

解压 ZIP，在任务实际使用的 Python 环境安装包内 `requirements.txt`，然后从解压后的父目录运行：

```sh
python deterministic-pixel-art/scripts/pixel_art.py render --spec deterministic-pixel-art/assets/gem-16.json --out output/gem.png --preview output/gem-preview.png
python deterministic-pixel-art/scripts/pixel_art.py inspect --image output/gem.png --grid
```

更新 Skill 时，请把旧版备份移到 AI 不会扫描加载 Skill 的目录，避免同时加载两份。使用便携输出模式时，其他程序可能读到尚未写完的新文件。无论采用哪种输出模式，如果写入过程中程序崩溃或电脑断电，一组输出文件都可能只完成一部分；中断后请先检查文件是否齐全、内容是否完整，再继续使用。

## 验证结果与使用限制

v1.2.0 正式版已通过 165 项源码测试、106 项独立安装包测试和 43 张基准图片检查，并验证了重复打包结果一致、Skill 格式合规。包内 98 个文件中，97 个与已验收的开发包逐字节相同，另一个模块仅修改了版本号。`verification.json` 记录发布对应的提交、Windows/Ubuntu CI 结果和打包来源。

外部试用覆盖八类任务。记录中仍保留 LT04 最初画反方向、缺少早期版本，以及 LT08 早期过程记录不全的问题。这些试用不足以证明工具能普遍改善画质、缩短任务时间或节省 token。Minecraft 游戏内效果、其他字体的适配、512×512 像素的直接绘制和多个 AI 协作绘图仍未验证。自动检查通过后，仍需人工看图，确认图案含义和视觉效果符合要求。
