# v1.3.0 — scoped edits and portable asset delivery

2026-11-15. Install the complete Skill ZIP for the Python tools and guides. DSH users install the separate `dsh-skill-deterministic-pixel-art@0.1.2` bundle. Downloading either package does not update an existing installation.

## Editing and review

- Replace exact RGBA colors within explicit rectangles or a mask with `recolor`. Mappings use the original pixels simultaneously; shared colors outside the allowed area remain unchanged. `verify` checks the full RGBA difference, including RGB under transparent pixels.
- Review large named atlases in bounded native-size pages with `review_atlas.py`. The coverage record identifies the cells on each page; it does not establish that an agent viewed every image.
- Keep source files when outputs are rebuilt. Packaging preserves previous generated outputs during ordinary replacement failures, and layout records bind names and regions to their image pixels.

## Recipes and delivery

- Preview repeating tiles and scenes made from explicitly named tiles with `tile_preview.py` and `tile_scene.py`. These recipes show seams and placement; they do not infer terrain rules or repair artwork.
- Export existing, equal-size PNG frames with `animation_export.py`, explicit action ranges and millisecond timings. The delivery retains the original PNG bytes and a relocatable manifest. Optional GIFs are previews with explicit alpha/background handling; they do not replace the original frames.
- Use the [DSH bundle](../../integrations/dsh/README.md) with matching DSH core and Skill versions 0.2.2-rc.1 through rc.3, Node >=24.9.0 and Cordis ~4.1.0. Desktop and command-line profiles have separate installation steps.

## Input boundaries

`recolor` and `verify` require static PNG inputs with channel depth at most 8 bits. The CLI rejects non-PNG, high-depth PNG and APNG inputs before publishing outputs, rather than silently converting or comparing only one frame. Python APIs check the supplied decoded modes and frame counts; they cannot recover information a caller discarded before passing an image.

Embedded layout JSON is limited to 256 KiB of its actual serialized bytes, including escaped Unicode. Oversize records fail before outputs are written. Large standalone layout JSON files are not subject to this embedding limit; a workflow that embeds a fresh record still needs to fit it.

Python 3.10+ and Pillow >=10.4,<13 remain supported. `requirements.txt` pins Pillow 12.3.0 for reproduction. JSON v1 and the existing drawing APIs remain available; PNG import does not reconstruct original layers or indexed-color projects.

## Packages

The GitHub release provides the versioned Skill ZIP, a separate full-size logo ZIP, `package-manifest.json`, `verification.json` and `SHA256SUMS.txt`. The verification record identifies the source commit, corresponding CI and artifact hashes. [SkillHub packaging](../skillhub-distribution.zh-CN.md) produces a separate upload package from the same Skill; platform account permissions and review are independent of local validation.

These changes do not establish general improvements in artwork quality, model correction speed or token use. Animation export does not draw frames, and scene previews are not a game engine or an automatic perspective editor.
