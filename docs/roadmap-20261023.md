## M1 — fix obstacles and expose the shortest path

1. Make silhouette diagnostics visible on light, dark and custom backgrounds without modifying source artwork. Retain alpha semantics.
2. Offer clearly labeled native-size and integer-zoom background views within existing sheet budgets.
3. Let `render --preview` choose its background; keep the existing default. Expose preview/import/review alongside render/inspect/validate with short task-based examples.
4. Provide a complete minimal transparent grid; retain errors for unknown symbols rather than silently inferring transparency.
5. Diagnose hard-link publication failures with safe recovery options. Any portable mode must be explicit about weaker visibility/atomicity, preserve no-overwrite, and test ordinary failures and cooperating-writer races. Never automatically enable force.
6. Document supported dependencies versus fixed pixel reproduction; keep polygon behavior and old rendering defaults unchanged.

Acceptance: actual background/silhouette cases, no self-written preview helper needed, no-force compatibility scenario, no partial leftovers on simulated ordinary failures, meaningful concurrency checks, old render output preserved.

## M2 — named atlas and precise editing

1. Import PNG with verified layout into editable named cells, preserving dimensions/order and all decoded RGBA, including hidden RGB and partial alpha. Explain that layers/original objects are not reconstructed.
2. Provide a short path from import to replacing one cell and generating fresh metadata. Preserve stale-metadata rejection.
3. Check an explicitly allowed modification region or mask. Compare raw RGBA, count outside changes and identify their bounds; do not treat an enclosing bbox as proof that a hollow ring was respected.
4. Summarize existing per-cell facts rather than estimating automatic optical weight. Keep visual judgement separate.

Design constraints: old atlas/blit source-over semantics remain the default. Handle/reject incomplete layout coverage deliberately; never drop pixels outside named cells. Bound generated JSON as existing import does. New options must be compatible with old specs and Python API callers.

Acceptance: hover ring, transfer-only edit, hidden RGB, half alpha, indexed PNG, invalid/stale layouts, duplicates, padding/unused cells, overwrite refusal, and independently rerenderable editable examples.

## M3 — larger artwork and accurate assembly

Start with native 64/128 pixel artwork and a 256 pixel scene, not enlarged 16 pixel assets. The runtime's 8192-side/16,777,216-pixel cap is an engineering bound, not a verified creative capability.

Prefer semantic components for UI, objects/layers for scenes, and a shared complete silhouette for sprites. Tile work follows one accepted composition, palette and lighting brief.

Introduce a separate assembly manifest/workflow if needed; do not silently turn JSON v1 embedded data into unrestricted file imports. Record canvas size, each component's file/size/global placement, source crop and compositing intent. Use integer extents with exclusive right/bottom boundaries. Diagnose missing pieces, out-of-bounds placement and unintended overlaps/gaps. Exact copy and source-over are distinct, explicit operations.

Adjacent edge colors need not be equal. Only validate declared connectors/coverage contracts automatically; provide seam crops and a whole-scene view for semantic continuity. Context/bleed is reference or render padding, with a single owner for every final pixel to avoid double outlines/alpha accumulation.

Deliverables: an editable native 128x128 asymmetric sprite; a 256x256 original scene/components; a single-cell atlas editing example; exact assembly and seam-review artifacts. Compare a full-image render/crop/reassemble control where equality is mathematically expected. A clean geometric check does not certify artistic consistency.
