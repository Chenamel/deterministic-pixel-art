## 固定项目目标

**把 deterministic-pixel-art 做成 AI 容易上手、能够自主创作和精确修改、可检查并交付的通用像素资产 Skill。** 覆盖图标、精灵、通用 UI、Minecraft 风格与分块场景；同一套通用工具支持不同模型和创作风格，专项指导按需使用。

交付物是简明的 Skill 入口、确定性渲染/编辑工具、可修改配方及必要的艺术指导。固定以下五个目标，后续改动至少对应其中一项：

| 目标 | 用户能够得到什么 | 怎样验证 |
|---|---|---|
| 容易上手 | 从任务描述找到合适的命令、表示方式或配方 | 以分发说明、帮助、公开 API 文档及配方完成常见任务；若必须查内部实现才能知道如何调用，记录缺口 |
| 容易创作 | 自由表达造型、配色、光影、材质和 UI 状态，不被演示风格限制 | 新建不同领域、不同风格的资产；有意义的造型代码允许存在，避免反复编写通用文件/布局处理 |
| 容易修改 | 既有 PNG 和规格可继续编辑，指定区域之外保持原样 | PNG 无损往返；命名单元/区域局改后区外 RGBA 变化为 0，布局及必要元数据继续有效 |
| 能帮助判断质量 | 帮 AI 检查表达含义、轮廓、背景、状态、内容及接缝，并找到具体修改依据 | 核查指导是否容易发现、审阅是否提供可定位信息，以及代理能否据此修正；图片指标不冒充审美判断 |
| 能稳定交付 | 产物可复现、可编辑、能放进目标消费端；环境和写入问题可恢复 | 检查规格/PNG/布局一致、必要场景预览和错误恢复；按实际环境验证，不以单次运行宣称全平台支持 |

正确性、数据保护和现有兼容性是底线；当前优先降低使用负担。艺术指导仍是产品组成部分，追求它能帮助不同任务，而非要求 AI 从此自动画出最佳作品。技术入口收短和指导发现路径可以一起改进。

## 范围与开发取舍

样例用于暴露问题、验证修复能否迁移；修好一张图本身不算工具改进。通用核心继续保持 JSON v1、现有公开 API 和已约定默认像素语义兼容，运行依赖保持 Python 与 Pillow；不因单例画风增加强制调色板或边距。

尚未开始的 LT04 地图、齿轮和提手润色候选停止排期。已有原图、修正版和审阅证据保留，LT04 原始失败不改成通过；后续工具评估无需等待这组图达到审美满意。新的绘画任务必须先写清它要回答的工具问题，避免继续追着单张图片打磨。

## 外部反馈怎样进入开发

| 类型 | 判断依据 | 处理方式 |
|---|---|---|
| 渲染或数据缺陷 | 合法输入未按约定生成像素，或导入、编辑破坏数据 | 做最小复现，修运行时，检查原输入及兼容性 |
| 可复用的使用障碍 | 入口找不到、需要反复抄布局、重复写通用胶水，或报错不能指导恢复 | 先检查现有命令、帮助和配方；用最小改动缩短路径，再用新资产验证 |
| 指导缺口 | 用户意图检查、修改范围或必要视觉检查缺失，且现有指导确实未覆盖 | 补短而具体的步骤；已有内容先改善发现方式，不重复堆教程 |
| 单次创作选择 | 地图形体、齿轮重量、提手高光等，规格与渲染一致 | 保存为诊断案例；只有发现可迁移的指导或工具缺口才进入开发，不自动转成修图任务 |

艺术指导属于 Skill 的价值范围，但不能从一个模型的一张图推导通用配色、描边或像素数量规则。样例变好也不能代替另一个任务中的使用证据。

## 怎样判断改进有效

关注实际完成与具体负担：能否找到正确入口、错误调用和恢复情况、可避免的辅助代码、手抄布局次数、局改区外像素变化、是否需要协调端救场，以及有记录的修改轮次。自定义造型代码有其价值，不以“零辅助代码”为统一目标。

视觉审阅用于发现方向、状态、关键内容遮挡及场景适配问题，并检验指导是否能帮助代理修正；不要求每幅样例达到最佳审美才推进工具。时间与 token 只报告实际取得且口径一致的数据，不由步骤数、字符数或主观印象推算。

用户2026-10-30已选择新的正式验收路线：正确性、兼容性和外部任务闭环优先；原两环境×八任务×两版本、至少六项受控收益设计转为长期研究，不再阻塞工具发布。已有材料不回填为受控结果，未取得的数据不作收益宣传。
